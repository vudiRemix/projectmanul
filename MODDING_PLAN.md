# ProjectSkins: план реализации

Статус: согласование архитектуры, код ещё не написан.
Целевая платформа: Minecraft Java Edition 1.20.1, Forge, Java 17.
Точные версии Forge и TACZ предстоит зафиксировать перед сборкой и проверкой.

## 1. Подмена текстуры

- Проверить исходники Minecraft 1.20.1: получение текстуры в PlayerRenderer, обычные руки в ItemInHandRenderer и путь рендера рук установленной версии TACZ.
- Основная точка интеграции: клиентский Mixin в AbstractClientPlayer.getSkinTextureLocation(). Подмена только возвращаемого ResourceLocation по UUID игрока.
- Если готового кастомного скина нет, возвращается штатная текстура. Во время загрузки нового URL сохраняется предыдущая рабочая текстура.
- Не использовать GameProfile, SkinManager, отмену RenderHandEvent, ручную отрисовку рук или изменения PoseStack.
- Дополнительный RenderLayer не нужен: основной скин заменяется в существующей отрисовке. ItemInHandRenderer, PlayerRenderer и TACZ продолжают управлять моделями и анимациями.
- Не менять геометрию/тип рук игрока: PNG 64×64 сам по себе не содержит признака slim/classic.
- После изменения кэша обычный следующий кадр использует новую текстуру; пересоздание сущности и отдельная перерисовка модели не нужны.

Предварительная проверка официальной ветки TACZ 1.20.1, commit b482eff8c94a733ac8d0910193fca3893954027c: LeftHandRender и RightHandRender передают анимированные преобразования в RenderHelper.renderFirstPersonArm; он вызывает стандартные методы PlayerRenderer.renderLeftHand/renderRightHand. Это исследование исходников, не подтверждение работы в игре.

## 2. Сервер и команды

- Зарегистрировать /projectskins <skin_id|url> <nickname> с проверкой прав оператора (уровень 2).
- Разбирать URL как один аргумент до пробела, чтобы двоеточия и слеши не требовали кавычек.
- Найти онлайн-игрока по никнейму, далее использовать его UUID.
- Проверить локальное имя либо URL; недопустимое значение не меняет текущее назначение.
- Хранить серверное назначение UUID → источник скина и номер изменения.
- При успешной команде немедленно отправлять SkinSyncPacket всем подключённым игрокам, включая владельца.
- При входе выдавать новому клиенту полный снимок назначений. Кэш не должен зависеть от того, загружена ли уже сущность другого игрока.
- Обеспечить сохранение клиентского назначения при респавне, смене измерения и повторном появлении игрока в зоне видимости.
- Очищать состояние подключения при выходе/смене сервера; серверное состояние отделить от других миров и запусков сервера. Сохранение назначений после перезапуска в текущий объём не включено.

## 3. Сеть

- Использовать Forge SimpleChannel с явной версией протокола и пакетами только server → client.
- SkinSyncPacket: UUID, тип источника, skin_id/URL, номер изменения.
- SkinSnapshotPacket: полный снимок для нового подключения, с ограничением размера и разбиением при необходимости.
- Обработчик передаёт обновление на клиентский поток, не загружает изображение в сетевом потоке.
- Клиентские классы не должны загружаться на выделенном сервере.
- Для работы мод требуется на сервере и у всех клиентов.

Источник API: https://docs.minecraftforge.net/en/1.20.1/networking/simpleimpl/

## 4. Локальные скины

- Путь: src/main/resources/assets/projectskins/textures/skins/<skin_id>.png.
- Ресурс: projectskins:textures/skins/<skin_id>.png.
- Допустимые имена ограничить строчными латинскими буквами, цифрами, подчёркиванием и дефисом; исключить переходы по каталогам.
- Проверять существование ресурса и PNG 64×64. Список встроенных ресурсов генерировать при сборке, чтобы он читался и из JAR на сервере.
- У клиентов должен быть тот же комплект встроенных скинов. Добавление PNG в исходники требует пересборки и установки обновлённого JAR.

## 5. URL и кэш

- Принимать HTTPS с точными хостами imgur.com и i.imgur.com и окончанием пути .png; без логина, нестандартного порта, query и fragment.
- Валидировать адрес на сервере и повторно на клиенте. Не принимать домены наподобие imgur.com.example.org.
- Перенаправления либо отклонять, либо проверять по тем же правилам на каждом шаге; не следовать им без проверки.
- Загружать в фоновом исполнителе с таймаутами, ограничением размера ответа и количества одновременных задач.
- Проверять реальный формат PNG и размеры до регистрации текстуры; расширение URL не гарантирует содержимое ответа.
- Кэшировать на диске под хешем нормализованного URL, проверять файлы кэша перед использованием. Ограничить размер кэша и освобождать неиспользуемые текстуры.
- Регистрировать готовую динамическую текстуру на клиентском/render-потоке.
- Проверять номер изменения и идентификатор подключения перед применением результата. Медленная старая загрузка не должна заменять более новый скин или попадать в другую серверную сессию.
- При ошибке оставить прежнюю рабочую текстуру и сообщить причину на клиенте.
- Локальный/уже загруженный скин применяется после обработки пакета. Новый URL — после скачивания: мгновенное отображение до получения изображения невозможно.

## 6. Предлагаемые классы

| Класс | Назначение |
| --- | --- |
| ProjectSkins | Точка входа, регистрация общих компонентов мода. |
| SkinSource | Типизированный источник: локальное имя либо проверенный URL. |
| SkinValidator | Общие правила имён и адресов, без клиентских зависимостей. |
| LocalSkinCatalog | Каталог встроенных PNG для проверки команд на сервере. |
| ProjectSkinsCommand | Права, разбор аргументов, поиск игрока, сообщения об ошибках. |
| ServerSkinRegistry | Авторитетные назначения по UUID и номера изменений. |
| ServerSkinEvents | Синхронизация при подключении и очистка серверного состояния. |
| ProjectSkinsNetwork | Канал, версия протокола, регистрация и рассылка пакетов. |
| SkinSyncPacket | Обновление одного назначения для всех клиентов. |
| SkinSnapshotPacket | Исходное состояние для подключившегося клиента. |
| ClientSkinCache | Назначения по UUID, готовые ResourceLocation, защита от устаревших результатов. |
| SkinDownloader | Фоновая загрузка, проверка PNG и файловый кэш. |
| ClientSkinEvents | Очистка при отключении и обработка перезагрузки ресурсов. |
| AbstractClientPlayerMixin | Единственная подмена возвращаемой текстуры, без вмешательства в рендер. |

При реализации каждый класс получит комментарий о назначении, стороне исполнения и правилах потоков. Нетипичные участки будут объяснены отдельно.

## 7. Проверка

1. Зафиксировать точные зависимости, собрать JAR и проверить запуск выделенного сервера без клиентских классов.
2. Проверить команды, права, неизвестные имена, недопустимые URL и PNG другого размера.
3. Проверить передачу и восстановление пакетов, обработку полного снимка и гонку двух загрузок.
4. Запустить сервер и два клиента: команда меняет скин у владельца и наблюдателя; третий клиент при позднем входе получает актуальное состояние.
5. Проверить первое и третье лицо, обе руки, рукава, респавн, смену измерения, переподключение и перезагрузку ресурсов.
6. С конкретной версией TACZ проверить удержание оружия, прицеливание, выстрел, отдачу, перезарядку и смену оружия.
7. Проверить ошибки сети и отключение во время загрузки: без зависания основного потока, потери рабочего скина и применения устаревшего результата.

Результат реализации: исходники с комментариями, инструкция, собранный JAR при успешной сборке и отдельный список фактически выполненных проверок. Игровые проверки отмечать выполненными только после реального запуска.
