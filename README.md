# ProjectSkins

Серверные скины игроков для Minecraft 1.20.1 / Forge 47.3.19 / Java 17,
совместимые с TACZ 1.1.8. Мод ставится **на сервер и всем клиентам** (один и тот же JAR).

## Команды

```
/projectskins <skin_id> <nickname>   — встроенный скин, например /projectskins bazuev DED0KOT
/projectskins <url> <nickname>       — скин с Imgur, например /projectskins https://i.imgur.com/AbC123.png DED0KOT
```

- Нужен уровень прав 2 (оператор) или консоль сервера.
- `skin_id` — имя PNG из `src/main/resources/assets/projectskins/textures/skins/` без `.png`
  (символы `a-z 0-9 _ -`). После добавления PNG мод нужно пересобрать.
- URL: только `https://imgur.com/<ID>.png` или `https://i.imgur.com/<ID>.png`, без параметров.
  `imgur.com` приводится к `i.imgur.com`.
- Все изображения: настоящий PNG ровно 64×64, не больше 1 МиБ.

## Как это устроено

```
 оператор ──/projectskins──► СЕРВЕР
                              ProjectSkinsCommand: права, разбор, проверка источника, поиск игрока
                              ServerSkinRegistry:  UUID → (источник, номер изменения)
                              ProjectSkinsNetwork.broadcast(SkinSyncPacket) ──► ВСЕ клиенты
 вход игрока ───────────────► ServerSkinEvents: SkinResetPacket + все SkinSyncPacket ──► новый клиент

 КЛИЕНТ
   SkinSyncPacket ─► ClientSkinCache.apply
                       LOCAL: projectskins:textures/skins/<id>.png (ресурс мода)
                       URL:   SkinDownloader в фоне → PNG → DynamicTexture на игровом потоке
                     active: UUID → ResourceLocation
   Рендер: PlayerRenderer / ItemInHandRenderer / TACZ
           └► AbstractClientPlayer.getSkinTextureLocation()  ◄── Mixin подменяет только результат
```

Рендер не перехватывается: модель, руки, рукава, `PoseStack` и анимации остаются
полностью под управлением Minecraft и TACZ. Мод лишь отвечает на вопрос «какая текстура у
этого игрока» другим `ResourceLocation`. Поэтому новый скин появляется на следующем кадре
без пересоздания сущности. `GameProfile`, `SkinManager`, `RenderHandEvent`, отмена рендера и
ручная отрисовка рук не используются.

## Классы

### Общие (сервер + клиент)

**`ProjectSkins`** — точка входа `@Mod`. Регистрирует сетевой канал (обязательно на обеих
сторонах, иначе Forge не согласует протокол), вешает серверные события на
`MinecraftForge.EVENT_BUS` и через `DistExecutor` запускает клиентскую инициализацию
только на физическом клиенте. Так выделенный сервер никогда не загружает `Minecraft`,
`TextureManager` и прочие клиентские классы.

**`skin.SkinSource`** — неизменяемая запись «тип + значение» (`LOCAL bazuev` или
`URL https://i.imgur.com/…png`). Конструктор сам прогоняет значение через `SkinValidator`,
поэтому невалидный источник нельзя создать ни из команды, ни при декодировании пакета.
`parse()` решает, что ввёл оператор: подходит под шаблон имени — локальный скин, иначе URL.

**`skin.SkinValidator`** — правила без зависимостей от Minecraft. `localId()` пропускает
только `[a-z0-9_-]{1,64}` (исключает `../` и прочий обход каталогов). `imgurUri()` разбирает
URI и проверяет: схема `https`, хост *ровно* `imgur.com`/`i.imgur.com` (а не «содержит
imgur.com»), без логина, порта, query, fragment, путь `/<ID>.png`. Возвращает
нормализованный адрес на `i.imgur.com`, чтобы не зависеть от перенаправлений.

**`skin.PngValidator`** — проверка байтов PNG до загрузки в GPU: размер ≤ 1 МиБ, сигнатура,
заголовок IHDR с 64×64 (читается до декодирования — маленький файл с «огромными» размерами
не вызовет большого выделения памяти), длины и CRC всех блоков, наличие IDAT и IEND, затем
реальное декодирование через `ImageIO`. Используется сервером (встроенные скины), клиентом
(ресурсы, ответы Imgur, файлы дискового кэша).

**`network.ProjectSkinsNetwork`** — Forge `SimpleChannel` `projectskins:skins`, протокол `"1"`.
Оба сообщения зарегистрированы только как `PLAY_TO_CLIENT`. Обработчики выполняются на
главном потоке (`consumerMainThread`). Сам класс не ссылается на клиентский код: клиент
передаёт ему обработчики через `installClientHandlers()`. `broadcast()` шлёт
`PacketDistributor.ALL` — всем онлайн-игрокам, включая владельца скина, независимо от
дистанции.

**`network.SkinSyncPacket`** — одно назначение: UUID игрока, источник, номер изменения.
Передаётся источник, а не картинка: встроенный PNG уже есть в моде клиента, URL клиент
скачивает сам. UUID не меняется при смерти, респавне и смене измерения. Номер изменения
(всегда > 0) позволяет клиенту отбросить устаревший или повторный пакет. Длина строки
ограничена 2048 символами ещё при чтении из буфера.

**`network.SkinResetPacket`** — пустой пакет «начинается полный снимок». Клиент очищает
назначения и начинает новую «сессию», после чего приходят `SkinSyncPacket` по одному на
каждое назначение. Это избавляет от одного огромного пакета.

### Сервер

**`command.ProjectSkinsCommand`** — регистрация `/projectskins`. Аргументы принимаются одним
`greedyString`, потому что обычный строковый аргумент Brigadier не примет URL с `:` и `/` без
кавычек. Порядок: проверка прав → разбор → проверка источника (локальный — есть в каталоге)
→ поиск онлайн-игрока по нику → запись в реестр → рассылка всем. Ошибка на любом шаге не
меняет текущий скин. Есть автодополнение: имена встроенных скинов, затем ники игроков.

**`command.SkinCommandArguments`** — чистый разбор строки на ровно два слова (источник и ник
`[A-Za-z0-9_]{1,16}`); лишние слова — ошибка, а не молча игнорируются. Вынесен отдельно,
чтобы его можно было тестировать без Minecraft.

**`server.LocalSkinCatalog`** — список встроенных скинов. Gradle-задача `generateSkinCatalog`
при сборке проверяет каждый PNG (имя, 64×64, ≤ 1 МиБ) и пишет `projectskins-skins.txt` в JAR.
Сервер читает этот файл, а не клиентский `ResourceManager` (которого на выделенном сервере
нет), и ещё раз валидирует каждый ресурс. `require()` даёт понятную ошибку для команды.

**`server.ServerSkinRegistry`** — авторитетное состояние: `UUID → SkinSyncPacket`.
`assign()` выдаёт строго возрастающий номер изменения (даже при повторном выборе того же
URL). Работает только на серверном потоке. Хранится до остановки сервера, поэтому
переживает смерть, смену измерения и перезаход игрока. Между перезапусками сервера не
сохраняется.

**`server.ServerSkinEvents`** — события сервера: регистрация команды; при входе игрока —
`SkinResetPacket` + все текущие назначения (поздно подключившийся видит скины, выданные
раньше); при остановке — очистка реестра, чтобы следующий одиночный мир в том же процессе
не унаследовал скины.

### Клиент

**`client.ClientBootstrap`** — вызывается только на клиенте. Подключает обработчики пакетов к
`ClientSkinCache`, регистрирует `ClientSkinEvents` и слушатель перезагрузки ресурсов (F3+T,
смена resource pack), который переприменяет все назначения.

**`client.ClientSkinCache`** — сердце клиента. Хранит:
`active` — UUID → текстура, которую сейчас видит рендер; `loaded` — готовые текстуры по
источнику (одна текстура на всех игроков с одинаковым URL); `pending` — идущие загрузки.
`textureFor()` вызывается Mixin-ом каждый кадр и только читает карту. `apply()`:
локальный скин проверяется и применяется сразу; URL отправляется в фоновый пул (2 потока,
очередь 128), результат возвращается на игровой поток через `minecraft.execute`,
регистрируется как `DynamicTexture` и применяется, только если назначение всё ещё
актуальное. Пока URL качается, игрок остаётся в предыдущем рабочем скине; при ошибке
скин не пропадает, причина пишется в лог и в чат. Неиспользуемые динамические текстуры
освобождаются. `reset()` при выходе/новом снимке освобождает GPU-текстуры и отменяет
загрузки.

**`client.SkinAssignments`** — последние назначения по UUID без зависимостей от Minecraft.
Принимает только более новый номер изменения. `Request` — маркер конкретного назначения;
`isCurrent()` сравнивает его по ссылке и по номеру сессии. Так медленная загрузка старого
URL не перезапишет более новый скин и не «просочится» на другой сервер после переподключения.

**`client.SkinDownloader`** — блокирующая загрузка (только из фонового потока). Повторно
проверяет URL, сначала смотрит дисковый кэш `.minecraft/cache/projectskins/<sha256>.png`,
иначе качает с таймаутом подключения 5 с и общим 15 с, без перенаправлений, только
HTTP 200, с ограничением 1 МиБ даже без `Content-Length` (`LimitedBodySubscriber`).
Проверенный PNG атомарно пишется в кэш (через временный файл), кэш ограничен 128 файлами.
Ошибка записи на диск не мешает показать уже скачанный скин.

**`client.ClientSkinEvents`** — при отключении от сервера вызывает `ClientSkinCache.reset()`.
Респавн и смена измерения отключением не являются и скины не сбрасывают.

**`mixin.client.AbstractClientPlayerMixin`** — единственная точка вмешательства в рендер.
`@Inject` в `AbstractClientPlayer.getSkinTextureLocation()` на `RETURN`: ванильный метод
отрабатывает полностью, затем, если у UUID есть готовый кастомный скин, возвращаемый
`ResourceLocation` заменяется. `PlayerRenderer` использует этот метод для тела, рук и рукавов
в третьем лице, а `renderRightHand/renderLeftHand` — для рук от первого лица; TACZ 1.1.8
рисует анимированные руки через те же методы `PlayerRenderer`. `cancellable = true` нужен
только чтобы подменить возвращаемое значение, событие рендера не отменяется.

## Сборка

Нужен JDK 17 (Gradle 8.1.1 не запускается на Java 21). Если JDK 17 не найден, плагин foojay в `settings.gradle` скачает его сам; можно и указать вручную:
`JAVA_HOME=путь/к/jdk-17 ./gradlew build`.

```bash
./gradlew build
```

Готовый JAR: `build/libs/projectskins-1.0.0.jar`.

## Ограничения

- Тип модели (slim/classic) не меняется: PNG 64×64 его не содержит, используется модель игрока.
- Голова в списке игроков (Tab) берётся из `PlayerInfo` и не подменяется.
- Назначения не сохраняются после перезапуска сервера.
- Скин по URL появляется после скачивания на каждом клиенте; до этого виден прежний скин.
